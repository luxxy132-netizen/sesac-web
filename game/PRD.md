# PRD — 모바일 게임 인앱 결제 대시보드

**작성일** 2026-08-12
**대상 배포** GitHub Pages (`https://luxxy132-netizen.github.io/sesac-web/game/`)
**디자인 기준** Montage (`@wanteddev/wds`) 토큰, 포인트 컬러 red — 루트의 서울 아파트 대시보드와 동일 토큰 재사용
**데이터** `mobile_game_inapp_purchases.csv` (3,024명 · 13개 컬럼 · 국가 27 · 장르 15, 결제일 2025-01-01 ~ 2025-08-13)

---

## 1. 배경

모바일 게임 유저 3,024명의 인앱 결제 원본 데이터는 있지만, 지금은 CSV를 열어 눈으로 훑는 수준이다.
운영 회의에서 "이번 달 매출은 누가 만들었나", "어느 국가·장르에 리소스를 더 쓸까"에 대한 답이
매번 새로 집계된다. 이 데이터를 매일 아침 열어보는 상시 화면으로 만든다.

## 2. 페르소나

**라이브 운영 PM**

- 매출 목표를 책임지는 실무자. 프로모션·상품 구성·이벤트 타이밍을 결정한다.
- 아침에 대시보드를 열고 "돈이 어디서 나오는지"를 먼저 확인한다.
- 고래(Whale) 유저의 이탈·집중도에 민감하다. 소수가 매출을 좌우한다는 걸 안다.
- 신규 팀원·타 부서에 화면을 그대로 보여주며 설명하는 일이 잦다. **용어를 모르는 사람도 화면 안에서 바로 이해할 수 있어야 한다.**

### 사용자 시나리오

1. **아침 매출 점검** — 대시보드를 연다. 총 매출·결제 유저·ARPPU·고래 매출 비중 4개 숫자를 훑고 오늘의 우선순위를 잡는다.
2. **고래 진단** — "고래가 몇 명인데 매출의 몇 %지?" → 세그먼트 스택 바와 카드 3장에서 인원·매출·ARPPU를 한 번에 확인한다.
3. **시장 판단** — "다음 분기 어느 국가에 마케팅 예산을 더 쓸까?" → 국가 랭킹을 매출/ARPPU/고래 수 기준으로 번갈아 정렬한다.
4. **장르 판단** — "인도에서는 어떤 장르가 돈이 되나?" → 국가를 India로 필터하면 장르 랭킹이 인도 기준으로 재계산된다.
5. **설명** — 신규 팀원이 "Minnow가 뭐예요?" → 지표 옆 물음표에 마우스를 올려 정의를 보여준다.

## 3. 목표 / 비목표

### 목표

- G1. 화면을 연 지 **5초 안에** "매출 규모 / 결제 유저 수 / 고래 의존도"를 파악한다.
- G2. **국가 × 장르** 두 축의 필터 조합으로 모든 KPI·랭킹이 동시에 재계산된다.
- G3. 세그먼트(Whale/Dolphin/Minnow)의 **정의와 실제 금액 기준**을 화면 안에서 확인할 수 있다.
- G4. 정적 호스팅(GitHub Pages)에서 빌드 도구·외부 라이브러리 없이 동작한다.

### 비목표

- 실시간 연동, 로그인, 유저 개별 조회 (데이터가 스냅샷 1회분)
- 시계열 추이 분석 — 원본에 `LastPurchaseDate`(마지막 결제일) 하나뿐이라 월별 추이로 해석하면 오독을 부른다. 이번 범위에서 제외.
- 리텐션·LTV 예측 등 모델링

## 4. 데이터

| 컬럼 | 사용처 |
|---|---|
| `Country` (27개) | 필터 축 1, 국가 랭킹 |
| `GameGenre` (15개) | 필터 축 2, 장르 랭킹 |
| `SpendingSegment` (Whale/Dolphin/Minnow) | 세그먼트 분석 |
| `InAppPurchaseAmount` (USD) | 모든 매출 지표 |
| 나머지(Age/Gender/Device/PaymentMethod/Session*) | 이번 범위 미사용 |

### 데이터 품질 (화면에 명시)

- **결제 금액 결측 136명** — 결제 이력이 없는 유저로 보고 매출 집계에서 제외, 전체 유저 수에는 포함.
- **국가 결측 60명 / 장르 결측 60명 (둘 다 결측 1명, 합 119명)** — 결측인 축의 랭킹에서만 제외한다. 국가만 비어 있는 유저는 장르 랭킹에는 그대로 들어간다. 총 매출에는 포함되므로 랭킹의 매출 합계는 총 매출보다 작다.
- 금액 결측군과 국가 결측군은 겹치지 않는다(0명).

## 5. 기능 요구사항

| ID | 기능 | 상세 |
|---|---|---|
| F1 | 필터 바 | 국가 select(전체+27), 장르 select(전체+15), 초기화 버튼. 화면 전체를 한 번에 스코프. |
| F2 | KPI 4장 | 총 매출 / 결제 유저 수 / ARPPU / 고래 매출 비중. 필터 적용 시 전체 대비 비중을 보조 문구로 표시. |
| F3 | 세그먼트 스택 바 | 매출 비중 100% 가로 스택. 세그먼트 간 2px 서피스 갭, 범례 상시 노출. |
| F4 | 세그먼트 카드 3장 | 인원·인원 비중·매출·매출 비중·ARPPU. 카드마다 정의 툴팁. |
| F5 | 국가 랭킹 | 매출 / 결제자 / ARPPU / 고래 수 정렬 가능. 셀 내 막대로 크기 표현. 행 클릭 시 해당 국가로 필터. |
| F6 | 장르 랭킹 | 국가 랭킹과 동일 구조. 행 클릭 시 해당 장르로 필터. |
| F7 | 용어 툴팁 | 물음표 버튼(hover + 클릭 + 키보드 포커스). ARPPU·세그먼트 3종·고래 매출 비중에 부착. |
| F8 | 데이터 품질 각주 | 결측 처리 방식과 데이터 기준일을 화면 하단에 명시. |
| F9 | 반응형 | 모바일 1열 / 태블릿 2열 / 데스크톱 4열 KPI, 랭킹 2단. |

### 교차 필터 동작

- 국가를 선택하면 **장르 랭킹**이 그 국가 기준으로 재계산되고, 국가 랭킹은 전체 국가를 유지한 채 해당 행만 하이라이트한다(비교 맥락을 잃지 않기 위함).
- 장르를 선택하면 반대로 동작한다.
- 같은 행을 다시 클릭하면 필터가 해제된다.

## 6. 비기능 요구사항

- **의존성 0** — 외부 CDN·프레임워크 없음. 순수 HTML/CSS/JS + 손으로 그린 SVG. (CSP·오프라인 안전, 기존 대시보드와 동일 원칙)
- **데이터 페이로드** — 원본 CSV(355KB)를 컬럼 인덱스 방식 JSON으로 압축해 배포. 목표 100KB 이하.
- **접근성** — 색만으로 정보를 전달하지 않음(범례+수치 병기), 모든 인터랙션 키보드 접근 가능, 툴팁은 `aria-describedby` 연결.
- **차트 규격** — dataviz 규칙 준수: 세그먼트는 순서형(ordinal) 단일 색상 램프, 랭킹 막대는 단일 시리즈 단색, 이중축 없음, 값은 표로도 읽을 수 있음.

### 색상 (검증 완료)

- 세그먼트 순서형 램프: Minnow `#FF9090` → Dolphin `#F03A3A` → Whale `#9C0F0F`
  (단일 색조 8°, 인접 ΔL ≥ 0.06, 밝은 끝 대비 2.18:1 — ordinal 체크 전항목 PASS)
- 랭킹 단일 시리즈: `#E52222` (흰 배경 대비 4.58:1)

## 8. 구현 계획

1. `build_game_data.py` — CSV → `game/data/purchases.json` (dims + 인덱스 행렬)
2. `game/index.html` — 시맨틱 마크업, 컨테이너만 정의
3. `game/assets/game.css` — 루트 `assets/dashboard.css`의 Montage 토큰 재사용 + 대시보드 전용 클래스
4. `game/assets/game.js` — 데이터 로드 → 필터 상태 → 집계 → 렌더(KPI/스택바/랭킹) → 툴팁·정렬·교차필터
5. 로컬 정적 서버로 검증(콘솔 에러 0, 반응형 3종, 필터 조합)
6. main 브랜치 병합 → GitHub Pages 자동 배포
